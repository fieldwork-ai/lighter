# Cache-profile comparisons on M1

All timing files retain three ordered samples per case: npm, pnpm, yarn, search, walk, copy, remove and watch, on a fresh VM with eight vCPUs, 4 GiB RAM and a 128 GiB sparse disk. Every arm passed six quiet filesystem/indexer samples ten seconds apart before starting. The native speed-floor reference used by these runs is retained separately; its search median is 1,233 ms. The floor is 200% of native speed, hence a maximum 616.5-ms median for this case.

At runtime `80518f3cc0a25b432e1846ee4ccf7c28433cad65`, default means 300-second positive/attribute/directory leases and 30-second negative leases. All numbered overrides set all four leases to that many milliseconds. The five-second experiment uses `80518f3-ttl-m1-{1-default,2-5000,3-5000,4-default}`. The ten-second experiment uses the preceding `4-default` as its first control, then `80518f3-ttl10-m1-{2-10000,3-10000,4-default}`. The twenty-second experiment likewise uses that ten-second experiment's final default control, then `80518f3-ttl20-m1-{2-20000,3-20000,4-default}`. Each extension was declared before its shared first control was measured. These experiments share controls; do not treat them as independent or pool their observations.

After the memory policy learned to withdraw compression steering under guest demand, runtime `129af505e8a72499ad150a114e19aebe986dd342` ran four new arms: `129af50-demand20-m1-{1-long,2-20000,3-20000,4-long}`. Both profiles are explicit overrides. Long sets attr/file/directory to 300000 ms and negative to 30000 ms; twenty sets all four to 20000 ms. The hot-directory cooldown remains unchanged. The final runtime `297f622` selects twenty-second defaults.

Each `.tree` identifies source and guest-artifact stamps. Profile values are supplied through `LIGHTER_FS_ATTR_MS`, `LIGHTER_FS_ENTRY_MS`, `LIGHTER_FS_DIR_ENTRY_MS` and `LIGHTER_FS_NEGATIVE_MS`. Ordinary `benchmarks/run.sh` performs the cases; neither the 30-second watch deadline nor the hardware gate's 100-ms median budget was relaxed. Five and ten seconds failed the search-speed floor in the earlier comparison. Twenty seconds has a measured search/copy cost, documented in the [release report](../../../../RELEASE-0.4.1.md).
