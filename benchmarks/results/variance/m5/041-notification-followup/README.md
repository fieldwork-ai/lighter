# M5 notification follow-up, 2026-09-07

These are diagnostic samples, not replacements for the full benchmark record or failed release qualifications. Host load was variable. All ordinary runs use eight vCPUs, 16 GiB guest RAM, a 128 GiB private disk, three repetitions and the unchanged npm-install/ripgrep/find-walk/copy-tree/watch-latency sequence. The original watch deadline is thirty seconds and median threshold is 100 ms. Comparisons observe the host for sixty seconds before each fresh VM.

- `exact-qualification-failed`: the exact `2e2bce5` M5 speed gate, watch 20004/445/1 ms. M5 passed eleven of twelve hardware gates; M1 passed all twelve. Retained as a failure.
- `activity`: control/active/active/control. Both variants load Foundation in the VMM; active additionally retains `NSActivityUserInitiatedAllowingIdleSystemSleep`. Values are 20003/697/1, 20005/960/1, 20002/1769/2, 785/1/2 ms. Both active arms failed the median threshold. The source is included; the private harness injects its dylib only into the VMM with `DYLD_INSERT_LIBRARIES`. No production activity assertion was added.
- `watch-baseline`: 0.4.0/current/current/0.4.0 with matching guest artifacts and no diagnostic injection. Values are 188/2/2, 1885/1/2, 2918/1/2, 1979/2/2 ms; every median is 2 ms. These observations did not reproduce the previous failed medians or establish a version effect. Corrected `.tree` metadata separates harness and runtime commits and records actual guest SHA-256 hashes. The original generic writer described the current checkout even for the old binary; original trees and independently recorded execution hashes were preserved privately. CSV measurements were not edited.
- `notification`: independent kqueue timestamps for request/reply vnodes and a separate FSEvents observer, plus a wrapper logging the VMM callback before invoking its original observer. The source of both helpers is included. The external FSEvents observer also sees guest writes and adds event-service load, so this is localization evidence, not an uninstrumented performance result. See the investigation document for the exact timestamps and limitations.
- `bundle`: bare/bundle/bundle/bare, the same `2e2bce5` example and guest artifacts. Both variants are ad-hoc signed with hardened-runtime options; the bundle has a private identifier and is not registered in Launch Services. The daemon reports no bundle ID for bare executables but recognizes the bundled executable. The first bare arm also overlapped read/hash work by a documentation helper; it must not be described as a quiet control. No application-layout or production runtime change was selected from this experiment.

Bundle watch samples, in arm order: 20003/395/2; 20000/355/2; 332/2/2; 1256/2/2 ms. These diagnostic trials do not convert any failed qualification into a passing one.

The helper sources are standalone test instrumentation, not linked into lighter. Build the observer with `clang -O2 -framework CoreServices notification-diagnostic.c`, the callback wrapper with `clang -O2 -dynamiclib -framework CoreServices notification-interpose.c`, and the activity helper with `clang -O2 -dynamiclib -framework Foundation activity-diagnostic.m`. The callback wrapper is specific to this VMM's streams sharing one callback implementation. Never use it as a general-purpose interposer.
