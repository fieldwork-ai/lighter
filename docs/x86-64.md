# Running x86-64 containers

`docker run --platform linux/amd64 …` runs under Rosetta. The Mac translates the container's x86-64 code with the same Rosetta that runs Intel Mac apps, at about two thirds of native speed on interpreter-style work and with TSO memory ordering in hardware; the emulator that stood in before ran at about a tenth.

## How it is wired

Rosetta for Linux is one arm64 binary at `/Library/Apple/usr/libexec/oah/RosettaLinux/rosetta`. It refuses to run anywhere but inside a virtual machine that Virtualization.framework has attached it to (`VZLinuxRosettaDirectoryShare`), which is one of the reasons lighter moved onto that framework. When the Mac has Rosetta installed, `lighter start` attaches the share and tells the guest so on its command line (`lighter.rosetta`); the guest's init mounts it at `/mnt/rosetta` and registers the binary with `binfmt_misc` as the handler for x86-64 ELF files.

The registration uses the `F` flag, and that flag is the whole trick. Without it the kernel resolves the interpreter path at `exec` time, inside the container's mount namespace, where `/mnt/rosetta` does not exist, so every amd64 container fails with a confusing `no such file or directory`. With it the interpreter is opened once, at registration, and the open file is what every later `exec` uses. `O` and `C` open the binary itself with the caller's credentials, which is what lets a setuid program inside a container behave.

## When Rosetta is not there

A Mac without Rosetta installed (it is a one-time Apple download) runs amd64 containers under `qemu-x86_64` instead, registered the same way; slower, and correct. `lighter doctor` says which of the two a machine will use, and `lighter rosetta --install` runs Apple's installer.

## What it costs

Measured on an M5 Pro (`docs/worklog.md`, 2026-09-05): a Python `hashlib.sha256` loop at 663k blocks a second native, 145k under Rosetta and 56k under qemu; a plain interpreter loop at 96 ms native, 152 ms under Rosetta and 1443 ms under qemu. For the common cases — an amd64 image that mostly waits on the network or the filesystem, a database, a build tool with an ARM version you have not switched to yet — the difference from native is smaller than those numbers suggest, because the translated code is not what is slow.
